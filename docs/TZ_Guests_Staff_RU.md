# ТЗ: гости, персонал, узнавание, качество трекинга

Статус: 03.10.2026 — реализовано (этапы 1–4): трекинг BoT-SORT+ReID с замерами (9.1), «Гість №N» и визиты,
вкладки «Гості» и «Персонал», очередь «Оберіть працівника», «Стійка без персоналу», подписи и клик по рамке в «Наживо»,
слой «Хітмап», зоны «Персонал»/«Черга», SAM 2 в разметке. Склейка треков: по месту и времени (≤ 20 с и ≤ 0.12 кадра или то же место ≤ 0.06
до 3 мин, внешность ≥ 0.5) и по внешности за день (≥ 0.80). Замер: у сидящей полускрытой гостьи сходство её же
треков 0.52–0.77 — ReID на потолочной камере слаб для сидящих, поэтому главное — место. Открыто: перепроверить пороги на загруженном дне.
Источник требований — живой просмотр реальной камеры «Вхід (двері)» (hybrid, Imou/Dahua) 03.10.2026.

## 1. Что просил пользователь

1. Прохожие в двери (за стеклом) не трекаются. **Сделано** (раздел 2).
2. «Зараз у залі 1, а по факту 2». **Сделано**: человек вне полигона зала больше не считается «у дверях / на вулиці».
3. Плохо с перекрытиями: два человека сливаются в одну рамку, треки рвутся.
4. На рамке подпись «Гість №N» (номер за день) и сколько он уже здесь.
5. Вкладка «Гості»: сколько зашло за день, список визитов, время, где сидел, запись визита (видео).
6. **Узнавание повторного гостя**: утром зашёл гость №1, днём зашёл снова — снова №1 (другой визит), завтра — тоже №1.
7. **Персонал**: добавить сотрудников, отметить один раз; дальше камера сама узнаёт сотрудника и считает
   его входы/выходы, время, где был. Если не уверена — плашка «Оберіть працівника».
8. Хитмап прямо на камере (слой в «Наживо»), а не только на «Головній».
9. Столики/кресла обвести один раз SAM2 — «красиво», по контуру предмета, а не прямоугольником.

## 2. Уже сделано (03.10.2026)

- Диагностика на архиве (1146 кадров, 4 мин): sub 640×480 при conf 0.3 — человек в зоне двери на **3** кадрах;
  main 1280×720 при imgsz 1280 — на **28** кадрах (conf до 0.86). Субпоток анаморфный, человек за стеклом ~15×40 px.
- Узел: размер инференса = ширина кадра (на GPU до 1280; на CPU — `YOLO_IMAGE_SIZE`), `pipeline.inference_size`.
- Hybrid/outdoor RTSP-камеры по умолчанию анализируют main; камера пользователя переключена на main.
- `/now` отдаёт `elsewhere` (в кадре, но вне зоны зала, например за стойкой); `outside` — только зона двери/тротуар.

## 3. Главный вопрос: узнавание людей и приватность

Сейчас инвариант (CLAUDE.md §5): **лица и идентичности не хранятся**. Пункты 6 и 7 его нарушают — нужно решение.

| Способ | Что даёт | Чего не даёт | Риски |
|---|---|---|---|
| **A. Внешность (одежда, силуэт), только в пределах дня** — ReID-вектор (OSNet), не картинка, удаляется в конце дня | Гость вышел покурить и вернулся днём → тот же №; склейка треков после перекрытий | Завтра (другая одежда) — новый номер | Низкие: не биометрия, хранится ≤ 1 дня |
| **B. Лицо (face embedding)** — для гостей | Узнаёт завтра и через месяц | Плохо работает с камеры под потолком (лица мелкие, сверху, в профиль) | **Биометрия**: закон о персональных данных / GDPR ст. 9 требуют явного согласия каждого гостя; табличка на двери не считается согласием. Для продажи заведениям — юридический риск |
| **C. Лицо — только для персонала** с письменным согласием сотрудника | Сотрудник узнаётся каждый день | — | Согласие в договоре/приложении; хранить только вектор, без фото; удаление по запросу |
| **D. Персонал без биометрии**: зона персонала (за стойкой) + внешность за смену + «Оберіть працівника» | Кто стоит за стойкой — сотрудник; за смену узнаётся по одежде/униформе | Утром новой смены — один клик «это Оля» на рамке | Низкие |

**Рекомендация:** гости — A (узнавание в пределах дня); персонал — D, с опцией C позже (после юр. решения).
Честность в UI: «Гість №7 · 2-й візит сьогодні»; повторное узнавание завтра не обещаем.

## 4. Качество трекинга (перекрытия)

- Модель `yolo11s` → `yolo11m` на GPU (4060 Ti тянет: сейчас GPU загружен на 2 %).
- Частота анализа 5 → 10 fps на GPU (меньше скачок между кадрами — меньше путаницы id).
- Трекер ByteTrack → **BoT-SORT с ReID** (встроен в Ultralytics, `with_reid`): сравнивает внешность при перекрытии.
- **Склейка треков** (A): трек пропал в зале и рядом в течение ≤ 20 с появился новый с похожей внешностью → тот же человек.
- Проверка — на архиве этой камеры: доля «разорванных» треков и слитых рамок до/после.

## 5. Модель данных (API, Mongo)

- `staff` — `{ venueId, name, role?, color, active }`. Без фото.
- `visits` — визит человека: `{ venueId, cameraId, day (локальная дата), personNo, role: guest|staff, staffId?,
  enterAt, exitAt?, dwellSec, tables[{id, sec}], trackIds[], confidence }`. Хранятся бессрочно (агрегатно полезно),
  без изображений.
- `people` (день) — `{ venueId, day, personNo, role, staffId?, embedding[], visits }`. Вектор внешности
  **удаляется в конце дня** (TTL), номер гостя — только внутри дня. В браузер вектор не отдаётся никогда.
- Нумерация: «Гість №N» — порядковый номер за день по закладу; новый день — с №1.

## 6. Узел обработки

- Для каждого трека — ReID-вектор (среднее по лучшим кадрам), сравнение с людьми дня (порог косинусной близости).
- Сотрудник: при пометке «это Оля» узел запоминает вектор на смену; совпадение ≥ порога → роль staff автоматически;
  неуверенно (серая зона) → событие «потрібне підтвердження» → в UI плашка «Оберіть працівника».
- Зона персонала (новый инструмент разметки): кто провёл в ней ≥ N с — кандидат в персонал → плашка.
- Протокол: `observations` дополняется `personKey` у трека; новое WS-событие `person_review`. Правки — обе стороны и README.

## 7. Интерфейс

- **Наживо**: на рамке «Гість №7 · 12 хв» (персонал — «Оля · бариста», другим цветом); клик по рамке → меню
  «Це працівник… / Це гість»; слой **Хітмап** (за сьогодні) рядом с «Рамки / Сліди / Розмітка».
- **Новая вкладка «Гості»** (`PageKey "guests"`): KPI дня (гостей, візитів, повторних, середній час, зараз у залі);
  таймлайн дня; таблица визитов (№, вхід, вихід, тривалість, де сидів, статус); карточка гостя — его визиты за день,
  кнопка **«Запис»** (клип из архива 24 ч, вход − 5 с … выход + 5 с; длинные визиты — переход в архив на это время).
  Старше 24 ч — честно «запис уже видалено (архів 24 год)». Выбор дня.
- **Персонал** (раздел во вкладке «Гості» или отдельный экран): список сотрудников, добавить/архивировать;
  по каждому — входы/выходы, время в зале/за стойкой, где был; очередь «Оберіть працівника».
- **Розмітка**: кнопка «Обвести автоматично (SAM 2)» — клик по креслу → контур предмета (до 32 точек), правится руками.

## 9. Решения пользователя (03.10.2026)

| Вопрос | Решение |
|---|---|
| Узнавание гостя | Внешность (ReID-вектор, без фото), **в пределах дня**; завтра — новый номер, UI честно так и пишет |
| Узнавание персонала | Зона персонала + внешность за смену; утром один клик «це Оля»; неуверенно → «Оберіть працівника» |
| Перекрытия | yolo11m + 10 fps + BoT-SORT с ReID + склейка треков |
| Записи | Клип визита (вход − 5 с … выход + 5 с, до 10 мин) + переход в архив; старше 24 ч — «запис видалено» |
| «Пройшло повз» | Человек был в проёме двери (зона двери), но **не пересёк порог** (линию дверей) |
| Превью человека | Вырез из архива **на лету** (не хранится; старше 24 ч — только номер) |
| Кто «Гість №N» | Пересёк порог внутрь **или** ≥ 30 с в зоне зала; персонал исключается |
| «Стійка без персоналу» | Да, в этом этапе: новые зоны разметки «персонал» и «черга» |
| Порядок | Трекинг → Гості → Персонал → Хітмап/SAM 2; показ на реальной камере после каждого этапа |

Инвариант CLAUDE.md §5 уточняется: **лица не хранятся; вектор внешности живёт ≤ 1 суток и не покидает API/узел**.

### 9.1 Замеры трекинга (03.10.2026, архив реальной камеры)

| Вариант | Треков ≥ 30 с | Сумма длинных треков |
|---|---|---|
| A: yolo11s + ByteTrack, 5 fps (было) | 3 | 144 с |
| C: yolo11m + ByteTrack, 5 fps | 1 | 60 с |
| D: yolo11m + BoT-SORT/ReID, 5 fps | 2 | 94 с |
| **E: yolo11s + BoT-SORT/ReID, 5 fps — выбрано** | 2 | 114 с |
| F: yolo11m + BoT-SORT/ReID, 10 fps | 1 | 60 с |

На 10-минутном прогоне то же: 10 fps и yolo11m давали больше коротких треков. Поэтому решение «m-модель, 10 fps»
не применено (по данным оно хуже на этой камере); BoT-SORT с ReID оставлен — он нужен для узнавания. Выборка мала
(~5–10 человек), перепроверить на загруженном дне. Сходство векторов: одновременно видимые разные люди — медиана 0.59,
95-й перцентиль 0.89; один человек после разрыва трека — 0.83–0.97 → порог 0.80 и запас 0.05 над вторым кандидатом.

## 10. UX: вкладки «Гості» и «Персонал»

### 10.1 Анализ: кто и зачем открывает эти экраны

| Кто | Вопрос | Что должно ответить за ≤ 5 с |
|---|---|---|
| Владелец, вечером | «Как прошёл день?» | KPI дня + лента дня: пики, сколько гостей, сколько вернулись, среднее время |
| Управляющий, днём | «Что сейчас?» | «Зараз у залі», кто сидит и сколько, кто ждёт у стойки |
| Владелец, по жалобе | «Что было с гостем в 14:20?» | Найти визит по времени → клип в один клик |
| Управляющий | «Где был бариста, сколько раз выходил?» | Лента смены: за стойкой / в зале / вышел; журнал входов-выходов |
| Утро смены | «Система узнала персонал?» | Плашка «Оберіть працівника» с кнопками-аватарами, 1 клик |

Выводы для дизайна:
1. **Время — главная ось.** Обе вкладки строятся вокруг ленты дня (Gantt): строка = гость/сотрудник, полоса = визит.
   Сразу видно «сколько», «когда», «как долго», и отсюда же — вход в запись.
2. **Одна сущность — одна карточка.** Клик по полосе, строке журнала или рамке в «Наживо» открывает одну и ту же
   боковую карточку (drawer): визиты дня, столики, путь по залу, клипы, действия.
3. **Подтверждения — сверху и в один клик.** Очередь «Оберіть працівника» — первое на вкладке «Персонал» и бейдж в меню.
4. **Честные пробелы.** Часы без анализа — штриховка; нет линии дверей / зоны персонала — blocked-карточка «Розмітити».

### 10.2 Навигация

- Два пункта меню: **«Гості»** (`PageKey "guests"`) и **«Персонал»** (`PageKey "staff"`) между «Головна» и «Камери».
  У «Персонал» — бейдж с числом неподтверждённых.
- Общая шапка: переключатель дня `‹ Сьогодні ›` + календарь (30 дней), фильтр камер (если их несколько),
  индикатор «наживо» для сегодня (обновление каждые 10 с).

### 10.3 Вкладка «Гості»

```
┌ Гості · Кав'ярня ───────────────── ‹ Сьогодні, 3 жовтня › 📅 ── ● наживо ┐
│ [Гостей 46] [Візитів 52] [Повернулись 6] [Сер. час 23 хв] [Зараз у залі 4]│
│ [Пройшло повз 310] [Конверсія 14 %]                                       │
├─ Стрічка дня ─────────────────────────────────────────────────────────────┤
│  людей ▁▂▄▆█▆▄▃▂▃▅▇▆▃▁         ← заполненность зала (та же ось времени)   │
│  08 ──── 10 ──── 12 ──── 14 ──── 16 ──── 18 ──── 20                       │
│  №1  ███        ██                 ← 2 визита, второй — «повернувся»      │
│  №2      ████████████              ← сидел за «Крісло-кокон» (тёмный тон) │
│  №3        ▌                       ← «зазирнув» < 1 хв (бледный)          │
│  ░░░░ штриховка — камера не аналізувала                                   │
├─ Журнал візитів ──── [Усі|Зараз у залі|Повернулись|За столиком|Зазирнули] 🔍 №
│ №  Вхід   Вихід  Тривалість  Де сидів           Статус        Запис       │
│ 7  14:02  —      18 хв ▮▮▮   Крісло-кокон 15 хв  ● у залі      ▶ Наживо    │
│ 1  13:40  13:52  12 хв ▮▮    —                  2-й візит      ▶ Запис     │
└───────────────────────────────────────────────────────────────────────────┘
```

- **KPI**: Гостей (уникальных за день) · Візитів · Повернулись (≥ 2 визитов) · Середній час (+ медиана) · Зараз у залі;
  вторая строка для hybrid: Пройшло повз · Конверсія. Сравнение с тем же днём прошлой недели — **только если есть данные**.
- **Лента дня**: спарклайн заполненности + строки гостей (виртуализированный список, 200+ строк без лагов).
  Ось — часы работы по данным, зум, линия «зараз». Тона: в зале `--s3`, за столиком — темнее, «зазирнув» (< 60 с) — бледно.
  Тултип «Гість №7 · 14:02–14:20 · 18 хв · Крісло-кокон»; клик — карточка гостя.
- **Журнал визитов**: сортировка, чипы-фильтры, поиск по номеру; длительность — число + мини-полоса; столики — чипы;
  «▶ Запис» генерирует клип (готуємо… / ▶ / недоступно — архів 24 год).
- **Карточка гостя (drawer)**: «Гість №7» — цветной круг с номером (не фото); «перший візит 09:12 · 3 візити сьогодні»;
  вертикальный таймлайн визитов: время, длительность, столики, **путь по залу** (след на кадре), встроенный плеер.
  Действия: «Це працівник…», «Об'єднати з гостем №…» (если ReID ошибся), «Це різні люди».
  Внизу: «Номер діє в межах дня. Обличчя не зберігаються.»
- **Состояния**: нет камеры с линией дверей → blocked «Позначте лінію дверей»; сегодня никого → пустая лента с «зараз»;
  день без покрытия → «Камера в цей день не працювала».

### 10.4 Вкладка «Персонал»

```
┌ Персонал ────────────────────────── ‹ Сьогодні › ── [+ Додати працівника] ┐
│ ⚠ 2 людини чекають підтвердження                                          │
│  [кадр 12:05 · за стійкою 6 хв]  (Оля) (Макс) (Це гість) (+ Новий)         │
├─ Зараз на зміні ──────────────────────────────────────────────────────────┤
│ (О) Оля · бариста      ● за стійкою   з 08:02 · 6 год 10 хв · виходила 4× │
│ (М) Макс · офіціант    ○ поза кадром  з 12:40 · 18 хв тому                 │
├─ Зміна (стрічка) ─────────────────────────────────────────────────────────┤
│ Оля  ████▒▒██████░░██████   █ за стійкою  ▒ у залі  ░ немає в кадрі        │
│ Макс           ██▒▒▒██                                                     │
├─ Стійка без персоналу: 3 рази, разом 7 хв (гості чекали) ─────────────────┤
└───────────────────────────────────────────────────────────────────────────┘
```

- **Очередь подтверждений**: карточка = вырез человека из кадра архива (на лету, не хранится дольше архива 24 ч),
  где и сколько был; кнопки-аватары сотрудников + «Це гість» + «Новий працівник». Клавиши 1–9 / `G`.
  После выбора узел запоминает внешность на смену.
- **«Зараз на зміні»**: аватар (инициалы + цвет), имя, роль, статус иконка+текст (за стійкою / у залі / поза кадром),
  начало смены, время на месте, сколько раз выходил, самое долгое отсутствие.
- **Лента смены**: строка на сотрудника, сегменты по месту, штриховка без анализа.
- **Карточка сотрудника (drawer)**: журнал «вийшла 10:14 → повернулась 10:22 (8 хв)» с клипами, итоги дня,
  7 дней по часам (BarChart); переименовать, роль, цвет, архивировать.
- **Справочник**: имя, роль (бариста / офіціант / кухар / адміністратор / інше), цвет. Без фото.
- **«Стійка без персоналу»**: минуты, когда у стойки (зона черги) гость, а за стойкой никого — ожидание.
  Нужны зона персонала и зона черги в разметке; иначе blocked.
- **Состояния**: нет зоны персонала → blocked «Позначте зону персоналу (за стійкою)»; нет сотрудников → «Додати першого працівника».

### 10.5 «Наживо» (связка)

- Рамка: «Гість №7 · 12 хв» (`--s3`), сотрудник — «Оля» его цветом, неподтверждённый — пунктир + «?».
- Клик по рамке → поповер: номер, визиты сегодня, «Відкрити картку», «Це працівник ▾», «Це гість».
- Слой **Хітмап** (за сьогодні) рядом с «Рамки / Сліди / Розмітка».

### 10.6 Визуальные правила

- Палитра — существующие токены (`--s1` зайшло, `--s2` повз, `--s3` в зале); цвета сотрудников — отдельный
  валидированный набор из 8 оттенков, не пересекается с рядами графиков; статус всегда иконка + текст.
- Табличные цифры (`tabular-nums`), время `HH:MM`, длительности «18 хв», «2 год 05 хв».
- Узкий экран: KPI в 2 колонки, лента дня скроллится внутри карточки, журнал → карточки.
- Drawer — `role="dialog"`, `aria-modal`, Esc; таблицы с `<th scope>`; контраст AA.

## 11. Дополнения пользователя (03.10.2026, после первого показа)

- **Гость только через порог.** Новый номер выдаётся лишь при пересечении порога внутрь. Трек в зале без входа — это
  кто-то из уже вошедших: склейка по месту/времени, по внешности, иначе ближайший «спрятавшийся» гость (вошёл, визит
  открыт, сейчас не виден). 60 с за стойкой без входа → плашка «Оберіть працівника» (персонал мог прийти до запуска камеры).
- **«Зараз у залі»** = видимые в зале + вошедшие, но скрытые (сидят за витриной/мебелью), пока не вышли через порог
  или не пропали на 3 мин.
- **Прохожие с доказательствами** во вкладке «Гості»: пешеходы и велосипедисты, график по часам, карточки с кадром и
  записью. Правило: не пересекал порог, двигался ≥ 0.025 кадра, уверенность детекции ≥ 0.45 (ночные отражения в стекле
  двери отсеиваются — проверено по ночному архиву).
- **Велосипеды**: узел детектирует класс bicycle; человек на велосипеде → велосипедист; велосипед без замеченного седока
  тоже велосипедист; пара «седок + велосипед» считается один раз. Велосипеды не входят в людей зала, входы, хитмап.
- **Маршруты гостей**: линии ног от входа до последнего места на кадре, сглаженные; «Куди сідали» — визиты по столикам.
- **Две рамки на одном человеке** (узкая + «человек со стулом», IoU 0.55 < NMS 0.7): склеиваются в старший трек на узле.
- **Персонал ушёл за стойку** → новый трек без входа продолжает невидимого сейчас сотрудника (за стойкой — приоритет
  персоналу, в зале — гостям). «Зараз у залі» = все внутри, кроме проёма двери и зоны персонала (гость у стойки
  с закрытыми ногами раньше выпадал из полигона зала).
- **Галерея за день** (идея пользователя «модель, что учится на людях за день»): у человека до 16 векторов из разных
  треков/ракурсов, сравнение с ближайшим; стирается в конце дня. Замер: девочка после выхода и возврата — 0.92 с одним
  из своих треков, но < 0.80 с усреднённым вектором → раньше получала новый номер.
- **Прохожие теряли треки**: прохожий в стекле 3–4 кадра (5 fps). На 5 мин архива: было 0 засчитанных, после
  (старт трека 0.3, первые 2 с — каждый кадр, минимум 2 точки) — 3 из ~9 появлений человека в проёме (часть из них —
  входящие). Дальше — счёт эпизодов по сырым детекциям на узле, если этого мало.
